# 使用与配置指南

[返回 README](../README.md) · [构建与诊断](DEVELOPMENT.md)

本页保留详细操作、客户端配置、发送状态及本地数据说明。快速上手请先阅读 README。

## 运行

运行发布目录中的 `ScreenShot.App.exe`，屏幕右侧显示 52px 的原生悬浮球（尺寸为逻辑像素，随 DPI 缩放）。拖动后吸附到显示器工作区左侧或右侧；左键展开工具栏和消息栏目，再次点击收起两者，右键选择隐藏或设置。隐藏后可通过托盘“显示悬浮球”恢复。默认 `Ctrl+Alt+S` 框选，托盘也提供截图、设置和退出。

悬浮面板使用原生 WinUI 控件、系统浅色/深色主题、图标提示和无障碍名称。上方横向工具栏为 `Codex | Agent | 复制 | 另存为 | 更多 | 下拉箭头`，下方为消息栏目；两者初始共同宽度约 520px，工具栏高度为 56px，消息栏目高度为 540px。两者左右边缘始终对齐，间距为 12px，在小工作区内限制窗口尺寸。左键拖动任一栏的四条边或四个角可调整大小：宽度同步变化，其余边缘分别调整各栏高度。当消息栏可见时，拖动窗口顶部外侧留白、工具栏顶部边缘或顶部角会改变整个窗口高度，保留工具栏高度，通过调整消息栏高度保持窗口底边位置。拖动范围限制在当前显示器工作区内，尺寸随 DPI 缩放。

按住工具栏空白处，或消息栏的“消息”标题及非滚动区空白背景，左键拖动可以改变面板位置。两栏一起移动并保持对齐，只有一栏可见时也能拖动。移动超过 4 个逻辑像素才开始调整位置；按钮、输入框、滚动区和可选择文本保留原有操作，边缘仍用于缩放。位置按鼠标所在显示器的工作区限制，并适配目标 DPI。本次运行中收起再展开、截图操作恢复及新截图会保留手动移动后的位置；退出重启后仍使用悬浮球附近的默认位置。

面板只保留一个下拉菜单箭头。两栏可见时，它位于工具栏右侧；菜单包含“隐藏工具栏”“隐藏消息栏”和“缩小工具栏”。缩小后保留 Codex、Agent 和同一个箭头，选择“扩展工具栏”恢复五个动作；消息栏保持原有宽度，只有工具栏可见时窗口收窄为小胶囊。小胶囊仍可移动和调整高度，扩展后恢复原有宽度。隐藏工具栏后同一个箭头移到消息标题栏右侧，供恢复操作。显隐文字随状态切换，恢复后保留消息、截图、提示词及原有高度。交替隐藏两栏时会显示另一栏，始终保留菜单入口。新截图确认后重新显示消息栏。

消息标题栏选择 Codex 工作目录，下方显示状态、对话及紧凑输入区。输入区只保留提示词输入框、发送按钮和 Codex / Agent 模式选择，默认 Codex；当前截图预览及“截取屏幕”按钮已移除。输入区内按 `Ctrl+Enter` 按所选模式发送当前截图和提示词，`Enter` 换行；有截图但提示词留空时使用默认提示词。本次面板内新截图与收起/展开保留模式选择。发送期间禁用模式切换，各目标独立防重发。工具栏的 Codex / Agent 按钮仍直接发送到对应目标。

用户截图和提示词显示在左侧气泡，Codex / Agent 回复显示在右侧气泡。左键点击缩略图可打开可缩放的截图详情。消息与截图会保存在本机，重启后恢复；Codex 原生会话也由 Codex 自身保存。“更多”可清空当前对话、发送到两端、复制提示词、退出截图或打开设置。再次点击悬浮球或在面板内按 `Esc` 会整体收起工具栏和消息栏并退出截图，当前图片和消息仍可在下次展开时查看。单独收起消息栏同样退出截图遮罩，但保留工具栏和当前内容。

用户提示词和 Codex / Agent 正文由原生 Markdown 渲染器展示，支持标题、粗体、斜体、删除线、行内代码、代码块、引用、列表、表格、分隔线及链接。每条消息使用一个连续的 RichTextBlock，可跨段拖选，正文获得焦点后 Ctrl+A 选中该条消息全部文字。代码块自动换行，表格以带列分隔符的连续文本行显示，与正文共享选择范围。每条回答（含历史回答）底部左侧提供小号复制图标，悬停提示“复制全文”，复制该回答完整 Markdown 原文，保留换行和代码；显示复制成功/失败状态，失败可重试。流式快照按约 80ms 合并渲染，最终回复立即刷新。链接仅允许有效的 HTTP(S) 地址；HTML 和 Markdown 图片语法保留为字面文本，不执行 HTML 或加载远程图片。此渲染器使用 WinUI 控件，没有 Web UI 依赖。

数学公式支持行内 `\(...\)` / `$...$` 和独立行 `\[...\]` / `$$...$$`。CSharpMath.Rendering 解析数学语法，WinUI 原生矢量显示分数、根式、上下标、希腊字母、集合/关系符号、求和/积分、矩阵、分段/对齐公式、专业运算符及带标注箭头；中文 `\text{...}` 优先借用 Windows 已安装的字体，缺字时保留源文本。宽公式随消息区域缩小，公式仍与正文共用一个选择范围，选择复制公式得到 LaTeX 原文；底部复制图标始终复制整条回答原文。未闭合的流式公式、不支持的命令、缺字或超出复杂度范围的公式保留源文本。仅排版数学子集，不运行完整 TeX 文档、宏包、TikZ、PGFPlots 或 Mermaid；绘图代码保留原文。

启动截图前隐藏自身悬浮窗口。无边框顶层 Overlay 覆盖整个虚拟桌面（所有显示器），冻结当前画面并显示半透明深色遮罩，鼠标为十字准星。拖动时按物理像素绘制原亮度选区；松开后保留选区并展开面板，尚未手动移动时定位在悬浮球附近。可以直接在遮罩上重新框选；零面积拖动不确认截图。遮罩上的 `Esc` 或右键退出；快捷键或“截取屏幕”重新获取桌面。

点击 Codex 后退出截图遮罩，保留当前图片、工具栏和消息栏目；从提交到回复结束始终保持面板可见。确认提交后持续更新 provider 的公开工作状态和回复文本，尚无输出时显示“正在思考 / 正在处理”，完成后展示最终回复并结束等待。正文在同一个气泡中更新；处于底部时自动跟随，向上翻阅时保留位置。发送状态与 Codex 回复分别标识，回复等待没有固定超时，生成时间长不会被误判为发送结果未知。失败或真实无法确认的提交仍提供明确反馈，禁止自动重发。保存对话框期间临时隐藏自身窗口，结束后恢复。Agent 直接调用配置接口，面板保持可见并显示回复。用户主动收起或关闭面板时，异步完成不会重新打开它。

拖动绘制采用保留的内存缓冲区，仅更新选区变化条带及旧/新边框；鼠标消息记录最新区域，像素合成在 `WM_PAINT` 执行，避免高频鼠标移动反复拷贝整个虚拟桌面。

不截图也可发送：展开消息面板，输入非空提示词，选择 Codex / Agent 后点击“发送”，工具栏目标按钮也使用同一规则。请求中不会附加空图片或占位图，用户气泡只显示文本；只有空白的无截图输入不能发送。Codex 仍需选择工作目录；Agent 不需要 Codex 目录。输入不同的新提示词可以再次发送，当前对话中已提交或结果未知的相同提示词仍按目标防重复提交，切换模式不解除锁定。后续消息会延续当前对话：Codex 通过公开 thread/resume 恢复自身上下文；Agent 使用此对话内已完成的 Agent 消息历史（包括历史截图），不同标签及不同客户端的上下文隔离。

截图已提交到当前目标后，输入新的提示词即可继续文字追问，发送按钮和 `Ctrl+Enter` 均可使用；追问不重复附带旧截图，图片仍保留在原消息和草稿中。另一个尚未提交图片的目标仍可发送该图，新截图会重新启用图片发送。原截图的未修改提示词和已提交/Unknown 的文字仍受防重发保护，切换标签及重启保持一致。

设置页的“默认提示词”支持多行内容；有截图时用户输入的非空提示词优先，输入留空或只有空白时使用该配置。默认值为“请描述并分析这张截图”，将设置留空时也恢复此值；Codex、Agent 和“复制提示词”使用同一规则。消息标题栏选择已配置的 Codex 工作目录，工具栏 Codex 或输入框旁的“发送”按钮发送。两端独立反馈。已提交或结果未知的目标对当前图片不允许再次发送；新截图会重置该图片限制。发送和等待回复期间禁用会改变当前任务的操作，消息栏目中的停止按钮在 Codex provider 模式请求中断当前生成，Agent 模式停止本地读取；两端均不重发。

## 对话标签与本地记忆

标签栏右侧、“＋”之前的小全屏图标可让消息栏填满当前显示器：工具栏和悬浮球暂时隐藏，标签置顶、对话内容铺满下方。再次点击图标或按 `Esc` 恢复原窗口位置、尺寸和工具栏状态。全屏内仍可切换/新建对话、查看历史和截图，发送与后台生成保持原流程。

输入区上沿中央的小箭头可收起提示词、发送按钮及模式选择：180ms 向下移动并淡出，完成后让出阅读空间；向上箭头保留，点击即可展开。截图和各标签的草稿保留，阅读折叠状态在本次面板内共享，重启默认展开；新截图完成后自动展开输入区。关闭应用或 Windows 的动画开关时直接切换。

全屏、新建、历史及输入区上下箭头均采用透明背景、无描边的小图标，保留点击区域和悬停提示。

消息栏顶部提供紧凑水平标签和“＋”按钮（`Ctrl+T`），在同一窗口新建、切换对话；标签较多时可横向滚动，方向键、Home/End 可切换标签。新标签继承当前标签的工作区和发送模式，随后独立保存工作区、草稿、截图、消息、发送任务与取消状态。不同标签可同时生成回复；“停止等待”只针对当前标签。关闭标签保留历史与正在运行的任务，重新打开后可继续查看结果。关闭整个面板或退出应用会停止本工具的所有等待，未确认任务重启后不自动重发。

新对话使用默认标题，第一条完整回复后通过当前客户端异步生成短标题；这是一次独立的标题请求，不加入用户对话上下文。右键标签可手动重命名，保存按钮和输入框聚焦描边跟随当前主题色；手动标题不会被迟到的自动标题覆盖。标签右侧的历史按钮可切换到已打开的对话、重新打开已关闭对话，或确认彻底删除本应用保存的对话与截图。删除确认在同一个历史弹窗内完成；取消返回列表，删除成功后立即刷新列表，运行中对话不能删除；Codex 原生历史仍由 Codex 管理。

本次运行的最新截图可发送给任意对话的工作区：截图后切换已有/历史对话或新建标签，都会自动带入图片，使用目标标签的工作区和 Codex / Agent 模式，保留该标签原有提示词草稿。正在发送的标签保持原请求图片快照，完成后在再次选中时接入最新截图。各标签独立保留当前截图的 Sent/Unknown 防重发限制；切换标签不会解除同一标签的锁，其他标签可以发送同一张图，失败可重试。重启后各标签恢复已保存的截图草稿。

存储目录为 `%LOCALAPPDATA%\AIScreenShot`：`conversations.db` 使用 Windows 自带 `winsqlite3.dll` 自动初始化，WAL 与 FULL 同步保存标题、标签顺序/选中状态、工作区、客户端、原生 thread/turn ID、消息状态及草稿；`screenshots` 保存 PNG。设置仍保存在 `settings.json`，API key 仍使用当前 Windows 用户 DPAPI 密文。对话内容和截图是用户要求的本地历史，不写进日志；运行日志在 `diagnostics` 子目录，显式 EXE 自测的生成图与检查报告仍在发布目录的 `diagnostics`。重启会恢复打开的标签和选中状态，Codex 的未确认回复通过公开 thread/read 核对，不读取内部数据库。部分坏记录会跳过并提示；损坏数据库先保留 damaged 备份再创建可用数据库，权限/磁盘错误不会静默删除旧数据。

拖动悬浮球时，两栏随球移动并受显示器工作区限制；球与工具栏垂直居中对齐，默认可见间距为 8 个逻辑像素，面板边缘保持圆角，没有连接尖角。标签选中颜色与主题强调色同步；标签溢出时，下方显示 10px 横向滚动条。删除确认框的“取消”为白色，“删除”跟随主题色，默认焦点保持在取消。第一版只实现各对话的会话记忆，不包含长期记忆、向量数据库、RAG、Agent tools 或跨对话共享。Codex 使用公开 provider，其自身可用工具受只读 sandbox 约束。

## 界面与主题

设置中的独立“动效设置”栏目提供关闭、简约、丝滑（默认）、弹性和灵动五种原生预设，速度可调 50%–200%，工具栏、消息面板、标签和消息交互可独立关闭。右侧显示专属标题与实际预览；调整即刻更新已打开窗口，“保存动效”只保存动效，“保存外观”只保存材质、主题等外观，两者均使用现有 settings.json。切换栏目保留草稿，关闭设置恢复各栏目未保存的修改。Windows 关闭动画时所有非必要过渡立即完成。

弹性使用独立的短弹簧周期和较低阻尼，保留微小回弹。简约显隐只淡化：打开前准备完整阴影，关闭保留两栏布局至淡出结束；阴影与正文同步淡化，共同淡化时复用模糊缓存和 GDI 缓冲区，不逐帧重新计算模糊或移动 HWND。截图前仍立即隐藏自身窗口。

新消息仅在容器首次插入时进入，流式文本更新不会重复播放；截图完成状态有短反馈，发送后的图片保留在消息气泡中。标签新建/关闭平滑进入和补位，按住标签水平拖动可改变顺序，后台任务和各标签草稿继续独立运行。动效保持现有原生卡片、材质、色彩和窗口定位逻辑；截图操作前仍立即隐藏自身窗口。

设置窗口使用 `NavigationView`，分为“常规与快捷键 / 外观与材质 / 动效设置 / Codex / Agent / 关于”，标题与说明位于设置行左侧，原生控件位于右侧；窄窗口自动上下排列，切换分类保留未保存输入。保存、工作目录选择及连接检测沿用原流程。

“常规与快捷键”底部提供“本地存储”卡片，显示本地 PNG 数量、总占用、保存路径及可清理数量，提供“打开文件夹”和“清理未使用截图”。打开设置、返回该栏目或重新激活窗口时刷新统计。清理无需保存设置：先显示确认范围，默认取消；只删除 screenshots 顶层符合本工具随机文件名规则、且未被任何消息/当前草稿使用的 PNG。关闭的历史对话、正在发送的消息和未持久化成功的本次运行草稿也受保护；旧 Images 集合只记录所有权，不代表图片仍在使用。“清空当前对话”本身仍不删除文件，后续可清理已无引用的旧截图。

清理逐个复核引用及文件大小/修改时间；新近被使用或变化的图片跳过，未知文件名、其他类型、子目录和链接保留。缺失、损坏、缺少必要数据表或无法完整读取的对话索引，以及 damaged 备份会禁用清理；清理检查不补建数据表或恢复数据库。结果显示实际删除数量、释放空间和跳过/失败数量，随后刷新占用。统计与清理在后台执行，关闭设置取消后续工作；此操作不保存其他设置，也不删除对话文字、Codex 原生会话或手动另存到其他目录的图片。

“外观与材质”新增“应用主题：明 / 暗 / 系统”和“主题颜色：跟随 Windows / 自定义颜色”。主题统一应用于设置、悬浮入口、消息面板及截图详情；系统模式监听 Windows 应用主题变化。自定义颜色通过原生 ColorPicker 选择，支持色谱、RGB 和 HEX 输入，用于按钮、选中指示和链接；自动选择高对比按钮文字，高对比度主题继续使用系统资源。跟随 Windows 时使用系统强调色，禁用自定义编辑器。修改实时预览，“保存外观”持久化，关闭设置撤销未保存修改；不会更改 Windows 配置。正文保持中性色，强调色用于交互状态，并可按比例混入两栏材质。

设置使用 Mica；悬浮界面没有公共底板，只由工具栏和消息面板直接绘制各自的圆角材质，宿主透明且不使用 HWND 或额外矩形裁切。“外观与材质”仅有两组 Acrylic / 轻透 Acrylic / 透明色层与 0–100% 背景不透明度，默认工具条 42%、消息 82%；两组均选择透明色层即可关闭额外模糊。文字、截图与按钮保持清晰，保留预览、保存、默认及关闭撤销。52px 悬浮入口保留原生交互及缩放过渡。

“外观与材质”提供“面板边框”开关及 0.5–3px 粗细滑块，默认开启/1px，工具栏和消息面板边框跟随主题颜色；关闭保留所选宽度。

“外观与材质”提供“面板阴影”开关、0–32px 扩散和 0–50% 不透明度，默认 12px/16%；两栏阴影只绘制在外围，内部透明、穿透输入、截图前同步隐藏。悬浮球复用同一组阴影配置，派生较小、较轻的主题色外阴影，随球显隐和移动。0–100% 材质主题色混入默认 18%，同步改变两栏的 tint / fallback；原背景不透明度独立，文字和截图不变淡。

“界面过渡动画”控制工具栏缩小/扩展、两栏显隐及悬浮球展开，默认使用 180ms 柔和过渡并尊重 Windows 动画开关；工具栏固定左端向右展开，阴影随实际两栏同步移动、收起。截图/操作前立即隐藏。底板、隐藏底板开关及底板材质/透明度配置已经移除；旧 JSON 自动忽略这些字段，保存时不再输出，保留两栏和业务配置。

统一尺寸与样式集中在 `App.xaml` 的 `SS.*` 资源中，详细 token、材质分层和验证范围见 [UI 设计说明](UI_DESIGN.md)。仅参考 [DeskBox](https://github.com/Tianyu199509/DeskBox) 的设计与实现模式，未复制其源码或资源，也未增加生产依赖。

## Agent

设置窗口的 Agent 分类用于配置模型接口。配置 Model name（服务商提供的模型 ID；发送截图时需支持图片输入）、Base URL（如 `https://api.example.com/v1`）、API key，点击“保存 Agent”。支持流式开关与 10–3600 秒请求超时；本机免认证服务可以留空 key，本机地址允许 HTTP，远程地址使用 HTTPS。API 根地址保留自定义路径，自动追加 `/chat/completions`，也接受完整的 completion endpoint。

点击工具栏 Agent，将当前截图和有效提示词通过 OpenAI compatible Chat Completions 接口发送，图片为 PNG data URL。用户内容与 Agent 回复显示在现有消息面板，支持流式 Markdown、停止等待和断流正文保留。回复气泡右上角显示接口响应的 `model`；接口未返回有效名称时显示本次请求的 Model name，长名称省略并可悬停查看。后续消息会携带当前标签内已完成的 Agent 对话历史（包括历史截图），不共享其他标签或 Codex 的上下文；不调用 tools，也不接入知识库。实现参考 [OpenAI Chat Completions API](https://developers.openai.com/api/reference/resources/chat)。

Agent 配置保存在 `%LOCALAPPDATA%\AIScreenShot\settings.json` 的 `Agent` 对象：`model_name`、`base_url`、`Stream` 和 `TimeoutSeconds` 为明文，API key 经当前 Windows 用户 DPAPI 加密后以 Base64 存在 `apikey_protected`。运行时 `ApiKey` 不参与 JSON 序列化，发送请求时解密用于 Bearer 认证；整个设置文件并未加密。换 Windows 用户或机器后可能需要重新填写 key，不写入日志或仓库。

“检测连接”使用当前未保存的配置调用 `/models`，确认认证和所填模型是否在列表中；不发送截图，不验证模型图片能力。部分兼容服务不提供 `/models`，可直接用截图测试。遇到不支持流式的服务时关闭流式。

key 使用 Windows DPAPI 的当前用户保护，JSON 仅保存 `apikey_protected` 密文；换机器或 Windows 用户后需重新填写。key、请求和远端错误正文不写日志。HTTP 明确拒绝允许用户修正后手动重试；发出请求后的网络错误、停止、超时、断流或无法确认的响应返回 Unknown，保留截图与已接收正文，禁止自动重发。

官网发送、浏览器扩展、Native Host、Named Pipe 和安装/注册脚本已移除，新包不再携带它们。旧设置中的 Browser 字段在首次加载时移除，其余配置保留；不会从本工具卸载浏览器中既有扩展或修改外部注册表。

## Codex

正常发送现使用 Codex CLI 的公开 App Server provider。无需打开 Codex 桌面窗口；发送后切换、收起或关闭桌面聊天不影响截图工具接收回复。实现参考 Amadeus 的 provider 事件路由，使用 .NET `Process` / JSONL 独立接入，不引入 Python、Electron、Web UI 或新的生产依赖。

1. 安装并登录 Codex CLI。若检测提示未登录，在终端运行 `codex login`。程序复用 CLI 管理的登录，不读取或保存登录令牌。
2. 在消息标题栏下拉菜单中点击“选择工作目录…”，使用原生文件夹选择器选择目录。最近选择的目录会保留；不会自动把旧的桌面项目名称推测为路径。
3. 截图并填写提示词，点击工具栏 Codex 或输入框旁的“发送”。图片以内存中的 PNG data URL 和有效提示词一起发送，助手回复在当前气泡中持续更新并渲染 Markdown。

留空 CLI 路径时，程序优先使用正在运行的 Codex 桌面内置 `codex.exe`，其次查找已安装的桌面运行时，再回退到 PATH 或标准 npm Windows 安装。设置中的显式 `.exe` 完整路径优先。设置页“检测 Codex provider”检查初始化、登录及所选工作目录的模型配置和图片能力，不创建聊天或发送消息。旧 CLI 的模型目录可能不包含桌面正在使用的新模型；检查失败时请使用桌面内置版本或升级 CLI，程序不会自动更换模型或降低 reasoning effort。

新对话通过公开 `thread/start` 创建持久会话（`ephemeral=false`），后续消息通过 `thread/resume` 延续本标签的会话，使用所选 `cwd`、只读 sandbox 和 `approvalPolicy=never`。会话标题以 `AI ScreenShot ·` 开头，可在 Codex 中查找；标题设置被拒绝时仍继续发送。助手用于分析并回答；需要交互或扩大权限的服务端请求不自动批准。沿用 CLI 的模型配置。图片、提示词和回复由 Codex 按正常聊天保存，不写入本工具内容日志；截图工具不访问 Codex 内部数据库。

先进行 `initialize` / `initialized` 握手，再调用 `thread/start` 或 `thread/resume`，随后提交一次 `turn/start`。准备与本地提交回执分别最多等待 90 秒，生成阶段持续读取到真实终态。有效 `turn/start` 回执才表示已提交；发送写入开始后丢失回执返回 Unknown，禁止自动重发。回复按 `threadId + turnId + itemId` 绑定，`item/agentMessage/delta` 更新同一气泡，完整 `item/completed` 修正正文，只有 `turn/completed` 才结束等待。最终优先使用 `final_answer`，不将过程文字或私人推理当作最终答复。协议以本机 CLI 生成的 schema 为准，官方流程见 [Codex App Server 文档](https://learn.chatgpt.com/docs/app-server)。

Codex 模式的“停止等待”通过公开 `turn/interrupt` 请求中断本次 `threadId` / `turnId`，保留已收到的正文，并等待 `turn/completed` 的 `interrupted` 状态后显示“Codex 已停止”。停止确认最长等待 15 秒；拒绝、超时或连接断开时明确显示未确认停止。若点击时提交回执尚未到达，先显示 Unknown，后台获得该次 turn 标识后再请求中断，不猜测标识、不自动重发。恰好自然完成时保留完成结果。Agent 模式仍取消本地请求和回复读取，无法确认兼容服务是否停止生成。退出截图程序会关闭它自己启动的 provider 进程。流中断会结束忙碌状态，已提交的消息不会变回可重发状态。此发送路径不读写系统剪贴板，也不查找、激活或操作 Codex 桌面控件。协议参考 [Codex App Server](https://learn.chatgpt.com/docs/app-server#api-overview)。

回复失败显示公开协议的错误类别及有效 HTTP 状态（如授权、额度、模型配置或连接问题），并保留已经收到的正文；自由格式的远端错误消息不会写入日志或直接回显。服务端连接重试期间继续等待 `turn/completed`，本工具不会再次提交截图或提示词。

旧 UI Automation 发送和剪贴板保护代码仍被窗口、欢迎页、手动发送专项诊断使用，不属于官网发送链路。正常 Codex 发送使用 provider；Agent 直接调用配置接口，不依赖浏览器扩展。
